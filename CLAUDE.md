# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Goal

This is Claude Terminal Assistant (formerly Terminal Claude Helper), a Windows tray app for **voice-controlling one chosen terminal while another app has focus**, for example while a full-screen game is running.

1. The user picks a **target terminal**. There are four ways: from the tray menu; with the terminals shortcut (`terminalsHotkey`, default Ctrl+Tab), which works like Alt+Tab; by holding the select button (default: mouse Back button, `config.json` → `select`) and left-clicking a terminal window; or by holding the mouse chord (Back + Forward) for `mouseHoldMs` (default 1.5 s), which opens a list of all terminals at the cursor, and left-clicking one while still holding. All open terminals are listed (Windows Terminal tabs, VS Code terminals, classic console windows). The target stays selected while other apps are focused.
2. Pressing the **global hotkey** anywhere starts recording from the microphone. Pressing it again stops recording. Recording also stops automatically after `maxRecordSeconds`. The hotkey is set in `config.json` → `hotkey`. A normal accelerator such as `Control+Alt+Space` goes through `globalShortcut`. A modifiers-only hotkey such as `Control+Alt` is watched by uiohook (`setupModifierHotkey`) and fires on a *clean tap*: the modifiers are released with no other key or click in between, so Ctrl+Alt+Del and AltGr letters don't trigger it. Pressing the mouse Back and Forward buttons together also toggles recording (`config.json` → `mouseHotkey`, a list of uiohook button numbers, default `[4, 5]`; `[]` turns it off). It fires once when the last button of the chord goes down (`setupMouseHotkey`). The chord starts recording even with no target terminal, because of **free dictation**: while the chord is still held, a left click on any window (Notepad, a browser, a chat) makes that window the destination of this one recording (`dictateAt` → `console-helper window x y`, shown as `→ <title>` after the REC timer). The text is then typed with `console-helper type <hwnd>`: the window is brought to the front (an Alt tap first, so `SetForegroundWindow` is allowed; an error if it still is not in front, so text never lands elsewhere) and sent as Unicode key events through `SendInput`. Screenshot paths are not added, and Enter is pressed only if `config.json` → `dictationEnter` is true (in a chat app Enter would send). The target terminal stays selected for the next recording.
   While recording, holding the select button and dragging captures that screen area. The screenshot is saved as a PNG under `screenshotsDir`, defaulting to `%APPDATA%claude-terminal-assistantscreenshots` and pruned after 7 days. Its path is placed in the dictated text where it was taken, and Claude Code attaches image files whose path it receives.
   **Screen recording**: while recording, a *tap* of the select button (press and release without dragging) turns screen recording on or off. Claude reads images, not video, so the monitor under the cursor is sampled every `screenRecord.intervalMs`; a sample is kept as a JPEG only when the screen changed or the pointer moved, with the pointer marked by a red ring. When the voice recording ends, at most `screenRecord.maxFrames` frames are kept (the first, then the biggest changes) and each is placed into the transcript at the word being said when it was taken, as `[m:ss] <path>`, followed once by a note telling Claude what the timestamps and the ring mean. The pill shows `🎥 n`, and a rising/falling two-tone cue marks on/off.
3. The audio is transcribed **locally** with whisper.cpp. No cloud STT is used.
4. The text is typed into the target terminal, followed by Enter if that option is on. The text is delivered **without moving focus**. Before that, a toast at the top right of the screen shows the text with Reject and Accept; Accept counts down `confirm.seconds` (default 3) and fires on its own if nothing is chosen (`confirm.enabled: false` sends at once).

## Commands

- `npm start`: run the tray app (Electron). Logs go to the launching terminal.
- `npm test`: run the unit tests (`node --test`, files `test/**/*.test.cjs`). Run a single file with `node --test test/whisper.test.cjs`.
- `npm run terminals`: print the terminals the app would offer as targets (JSON). Add `-- --all` to include hidden consoles that the filter removes.
- `node src/console-helper.cjs send <pid> <base64-utf8-text> <1|0>`: type text into a terminal by hand. This is useful for debugging injection.
- `npm run install-prompt` (`-- --uninstall` to undo): adds the "● Selected / ○ Not selected" line to the PowerShell 5.1/7 profiles (`CurrentUserAllHosts`), `~/.bashrc`, and Claude Code's `statusLine` in `~/.claude/settings.json`, plus the screenshots folder in that file's `permissions.additionalDirectories` (so Claude Code in any project opens dictated screenshot paths without asking; the pre-rename folder is dropped). `updateClaudeSettings` is the pure part, tested in `test/install-prompt.test.cjs`. Lines it adds carry `# claude-terminal-assistant` (lines with the old `# terminal-claude-helper` marker are replaced or removed too). cmd isn't covered because it has no programmable prompt.
- `npm run icon`: redraws `assets/icon.png` (256 px, used for the settings window and notifications) and `assets/icon.ico` (16–256 px, for shortcuts) from `appIconBitmap` in `src/tray-icon.cjs`.

## Architecture

The whole flow is orchestrated by `src/main.cjs` (Electron main process, CommonJS):

**hotkey** (`globalShortcut`, i.e. `RegisterHotKey`) → **recorder** (hidden `BrowserWindow`) → **Whisper** → **console helper**

- **`src/recorder.html` + `recorder-preload.cjs`**: a hidden window that captures the mic through `getUserMedia` into a 16 kHz `AudioContext`. It returns a 16-bit mono WAV over IPC (`rec:start`, `rec:stop`, `rec:audio`, `rec:error`). It also plays the audio cues (`rec:beep`), because the tray can't be seen during a full-screen game. `backgroundThrottling: false` is required.
- **`src/overlay.html` + `overlay-preload.cjs`**: a transparent, click-through, non-focusable, always-on-top window that follows the cursor (it is repositioned every 16 ms while shown). It shows a REC timer, a transcribing spinner, then the result or error. It can't appear above games in exclusive full-screen; borderless windowed works.
- **Click-to-select** (`setupClickSelect` in `main.cjs`): **uiohook-napi** provides global mouse and key hooks. Button numbers are 1 left, 2 right, 3 middle, 4 Back, 5 Forward. `select` can be `{ "mouseButton": n }` or `{ "key": "F13" }` (any `UiohookKey` name), which is useful when mouse software maps a custom button to a key. A left click while the button is held calls `console-helper at x y`, with physical pixels from the hook.
- **Screenshot drag** (`startDrag`/`updateDrag`/`endDrag` in `main.cjs`): the hook gives physical pixels; `selection.html` is a click-through frame window placed with `screen.screenToDipRect`, drawn just *outside* the area. The cursor pill is hidden during the drag so it can't end up in the shot. `console-helper capture x y w h file` copies the area with GDI `BitBlt` into raw BGRA (alpha forced to 255), and main turns that into a PNG with `nativeImage.createFromBitmap`. Shots are promises gathered in `shots` and awaited before sending.
- **`src/whisper.cjs`**: manages one long-running `whisper-server.exe`. It starts lazily, is pre-warmed when recording begins so the model loads while the user speaks, and is killed after `idleUnloadMinutes` to free VRAM for games. Audio is sent with `POST /inference` (multipart) as `verbose_json`; the server runs without `-nt`, so every word carries its start time (`timedWords`), which is how images are placed in the transcript. `transcribe` returns `{ text, words }`. Time zero is `rec:started`, when the microphone actually opened. Silence handling is two-layered because Whisper invents subtitle phrases on silence ("Să vă mulțumim pentru vizionare!", "Thanks for watching"). First, `peakLevel` (the loudest 30 ms RMS) below `silenceLevel` skips transcription entirely. Second, `isHallucination` drops transcripts that are only such a phrase. `cleanTranscript` removes Whisper's `[BLANK_AUDIO]` and `(music)` tags.
- **`src/screenrec.cjs`**: the testable half of screen recording. `sampleOf` turns a capture into a 160 px grayscale sample; `changeScore` is the largest per-block (16×9 grid) mean difference plus pointer movement, so a dialog in one corner counts as much as a full-screen change; `frameJpeg` draws the ring; `pickFrames` caps the count; `interleave`/`composeMessage` place images before the first word said at or after their time (never before a token glued to the previous word, such as punctuation). The capture loop (`startScreenRec`/`captureFrame`/`stopScreenRec` in `main.cjs`) copies the display nearest the cursor with in-process GDI `BitBlt` (`src/screen-grab.cjs`, about 30 ms for 1920×1080; `desktopCapturer` took about 250 ms). To keep the cursor pill out of the frame, it is set to opacity 0 for just that copy (`setOpacity` reaches a `BitBlt` at once; the pill is gone from the screen for 15–25 ms once a second). Do **not** use `setContentProtection` on the overlay: on this transparent window that is hidden and re-shown it made the pill invisible on the monitor too, and `BitBlt` without `CAPTUREBLT` does not leave out layered windows under DWM either.
- **`src/console-helper.cjs`**: all Win32 calls are made here through **koffi** (FFI, no native build step). It **always runs as a separate process**, started by `src/terminals.cjs` with Electron's binary and `ELECTRON_RUN_AS_NODE=1`. The reason is that `FreeConsole`/`AttachConsole` change process-wide state and must never run inside the app process.
  - `list`: walks processes (Toolhelp snapshot) and runs `AttachConsole` on each shell-like process. It reads the console title (for Claude Code this is the session name) and `GetConsoleProcessList`, then groups processes that share a console. The target `pid` is the console's **anchor**: the process whose parent is outside the console. Consoles that have no visible conhost window are kept only if their host process is a known ConPTY terminal (`TERMINAL_HOSTS`). This filter hides the invisible consoles of background tools.
  - `at`: `WindowFromPoint` → root window, matched to a console by its visible conhost hwnd, or by the pseudo-console window's **owner**. Windows Terminal owns each tab's `PseudoConsoleWindow` with its top-level window, one per WT window. If several tabs share a window, the WT window title (the active tab's title) decides. IntelliJ leaves its pseudo-console windows unowned, so its consoles are matched by host pid instead; when that still leaves several (the window title is the project, not the tab), `at` returns `{ ambiguous, windowTitle, candidates }` and main shows `picker.html`, a small always-on-top window at the cursor (click or a digit picks, Escape/blur/click elsewhere cancels). It is our own window on purpose: a native popup menu opened from the global hook while another app is in the foreground closes again at once.
  - `send`: runs `AttachConsole(pid)`, opens `CONIN$` and calls `WriteConsoleInputW` with key down/up `INPUT_RECORD`s. Newlines become spaces, and Enter is sent as `VK_RETURN`. The app sends Enter as a second `send` with empty text, 500 ms after the text (`ENTER_DELAY_MS`), for free dictation too: text and Enter in one batch reach the program as one input chunk, which Claude Code (an Ink TUI) treats as a paste, where Enter is a new line rather than submit. This works for conhost and ConPTY (Windows Terminal) alike, because the shell owns the console input buffer whichever app draws the window.
- **"Selected" line** (`src/statusline.cjs`, `shell/prompt.ps1`, `shell/prompt.bash`): reads the target pid from `state.json`. With `--plain` (shell prompts) the terminal counts as selected if that pid is attached to the same console (`consolePids`). Without it (the Claude Code status line) it counts if that pid is an ancestor. Git Bash's `$(...)` breaks the Windows parent chain, and Claude may run status-line commands in a hidden console of its own, which is why each mode uses a different check. In Claude Code mode the line also shows session info from the JSON Claude pipes on stdin (`claudeInfo` parses it, `segments` styles it with 24-bit colors): model with a 5-dot effort meter │ a context bar with tokens used/max (green <50%, yellow <80%, red after) │ prompt-cache time left until `prompt_cache.expires_at` out of its TTL (yellow under 25%, red under 10% or 2 min, `cold` once it expires) │ `next ~$X` the estimated cost of the next request, `cold $Y` what it would cost once the cache expires, and `Σ` the session total from `cost.total_cost_usd`. `estimateNext` bills the current context as a cache read while warm or a cache write (1.25× input for 5m, 2× for 1h) when cold, plus the last reply's output tokens; list prices live in `PRICES` (first-party API rates, matched by model-id prefix) and need updating when Anthropic changes them │ subscription usage from `rate_limits` (`five_hour`, `seven_day`, …: `used_percentage`, `resets_at`), shown as share left and time to reset (absent for API-key logins). `config.json` → `statusLine` tunes the line: `showNext: false` hides the `next`/`cold` estimate and leaves only the `Σ` total (`statusLineConfig` reads it on every run, so changes apply without a restart). `refreshInterval: 2` keeps the countdown live. Claude Code's Bash tool also runs in its own hidden console, so to test prompt mode, attach to the target's console first (`AttachConsole`) and run the shell from there.
- **Tray** (`src/tray-icon.cjs`, `menu.html`, `theme.css`): the icon is a microphone drawn with signed distance functions in the state's color (green ready, gray no target, red recording, yellow transcribing), at 16 and 32 px. A click opens `menu.html`, our own frameless window rather than a native menu: a status header (state lamp, recording shortcut as keycaps, where dictation goes, last text), the terminals as radio rows (`labels.cjs` names them like "PowerShell in Windows Terminal" and marks consoles running `claude.exe`), the Enter switch, and Start recording / Settings / Restart / Quit. It opens at once with the last known terminals and updates when `listTerminals` returns. The page reports its height (`menu:size`), main places it above the tray icon inside the work area. It closes on blur, Escape, or a click outside (hook); a tray click within 300 ms of closing doesn't reopen it. `Restart` is `app.relaunch()` + quit (the fresh copy picks up code and config changes, and is no longer attached to the terminal `npm start` ran in). `theme.css` holds the shared theme: neutral gray surfaces and text chosen for easy reading (secondary text about 7:1 on the background), with orange (#FF7A1A) as the only accent: primary buttons, switches, selection, the ready lamp. Recording is rose-red (#FF3355) and transcribing gold (#FFC83D) so neither reads as the accent; keycaps are in Cascadia Mono. `overlay.html`, `picker.html` and `selection.html` repeat these values inline; the tray icons, the app icon, the status line and the shell prompts ("● Selected") use the orange accent too.
- **Settings window** (`settings.html`, `settings-model.cjs`, `keys.js`): edits `config.json`. Shortcuts are recorded by pressing them: `keys.js` turns key events into an Electron accelerator, or modifiers alone (two or more, on release), or a uiohook key name for the select key; while a field listens, the app's own hotkeys are paused (`pauseHotkeys`, which also unregisters a `globalShortcut` so Windows doesn't swallow it). Saving validates (`validate`), writes the file in its own style (`formatConfig` reproduces the hand-written file exactly; a test checks it) and applies the change at once, except `RESTART_KEYS` (hotkey, mouse chord, hold time, select, whisper, screenshots folder), which are read at startup: then the button reads "Save and restart" and the app relaunches. Saving a restart change is refused while recording.
- **Terminal chooser** (`chooser.html`, terminal chooser section of `main.cjs`): one list at the cursor, two modes. *Mouse* (`showChooser`): pressing the mouse chord starts recording as before and lists terminals in the background; if the chord is still held after `mouseHoldMs` with no click, the list appears. A left click on a row, chord held, sets the target and cancels the recording (`cancelRecording`: the audio that still comes back is dropped); a click outside is free dictation; letting go with the list open cancels both. *Keys* (`chooserKey`): `terminalsHotkey` is registered with `globalShortcut` (RegisterHotKey, so the app in front doesn't also switch its tabs; it also means browsers and IDEs stop getting Ctrl+Tab while the helper runs), plus the same with Shift for moving up. The list opens at once with the known terminals, highlighting the one after the current target, and is replaced by a fresh listing keeping the highlight; letting go of the shortcut's modifiers (uiohook keyup) or Enter picks, Escape cancels, a click on a row picks. A recording in progress is not cancelled in keys mode. The window is `focusable: false` and shown inactive, so a game keeps the focus; main drives the highlight and the pick from the hook, with the row rectangles the page reports (`chooser:layout`).
- **Accept / reject toast** (`confirm.html`, `confirmSend` in `main.cjs`): after transcription, delivery (to the terminal or a free-dictation window) waits on `confirmSend`, which sets the phase to `confirming` (yellow tray icon, a short cue) and shows the toast on the monitor under the cursor. Like the chooser it is `focusable: false`; main owns the countdown and takes clicks and hover from the hook, with the button rectangles the page reports. Hovering the toast pauses the countdown; the recording shortcut or the mouse chord rejects (`toggleRecording` checks `confirming` first). A rejected text is dropped with a "Not sent" pill. The page exposes its API as `toast`, not `confirm`: `window.confirm` already exists and `exposeInMainWorld` cannot replace it.
- **Log** (`src/log.cjs`, top of `main.cjs`): `hookConsole` copies `console.log/info/warn/error` to `%APPDATA%\claude-terminal-assistant\logs\app.log` with time and level; over 1 MB at startup it becomes `app.old.log`. Also logged: uncaught exceptions and unhandled rejections (`logCrash`, which notifies once per run), and from every window (`web-contents-created`) console errors, preload failures and crashed page processes. Use a one-parameter `console-message` handler (Electron 35+ puts `level` and `message` on the event; extra parameters print a deprecation warning). Settings → General has Open log and Report a problem, which opens a GitHub issue (`package.json` `bugs.url`) with versions filled in but not the log, since it contains dictated text.
- **Start with Windows** (`applyStartAtLogin`): at every start, and on saving Settings, the app writes a per-user Run entry named "Claude Terminal Assistant" that launches this Electron with the project folder (`app.setLoginItemSettings`), so it is in the tray after sign-in; `startAtLogin: false` removes it. Writing it each time keeps it pointing at the project if the folder moves. Only one copy runs (`requestSingleInstanceLock`); starting another, e.g. `npm start` while the login copy runs, quits the new one and opens the running one's tray menu (`second-instance`). To load code changes, use Restart in the tray menu. Test instances started with `--user-data-dir` get their own lock and data, so they can run beside it.
- **State**: the target and the `pressEnter` toggle are saved to `%APPDATA%\claude-terminal-assistant\state.json`. The app was called Terminal Claude Helper before; at startup `main.cjs` moves the old `terminal-claude-helper` data folder over (or copies `state.json` and `screenshots` if the move fails), `statusline.cjs` falls back to the old folder, and `applyStartAtLogin` removes the old-named Run entry. At startup a saved target is kept only if that pid is still a listed terminal. If a send fails, the target is cleared.
- **Config**: `config.json` in the repo root holds `startAtLogin`, the hotkey, `terminalsHotkey`, `pressEnter`, `dictationEnter`, `confirm` (`enabled`, `seconds`), `mouseHoldMs`, `maxRecordSeconds`, the `statusLine` and `screenRecord` options, and the whisper `server`, `model`, `language`, `port`, `threads` and `idleUnloadMinutes`. It is read once at startup and edited from the Settings window, which writes it back.

## Environment facts

- The machine runs Windows 11 with an NVIDIA RTX 5070. whisper.cpp uses its CUDA build: `large-v3-turbo` loads in about 2.5 s, and a short command transcribes in about 0.3–0.5 s.
- whisper.cpp binaries and models are **reused from the sibling project**: `C:\Users\Andrei\Desktop\AI Assistent\data\whisper\` (`bin-gpu\Release\whisper-server.exe`, and `models\ggml-large-v3-turbo.bin` and `ggml-medium.bin`). They are referenced through `config.json`. Do not download them again.
- `uiohook-napi` loads its bundled `prebuilds/win32-x64` binary; its install script (a node-gyp compile) is denied on purpose.
- `npm install` blocks install scripts unless they are allowlisted (`allowScripts` in `package.json`). koffi is approved. If `node_modules/electron/dist` is missing after an install, run `node node_modules/electron/install.js`.
- When testing from Claude Code's shell tools, processes started by one command, such as a test terminal window, are killed when that command ends. Run setup, the action and the check in **one** command. Check `%APPDATA%claude-terminal-assistantstate.json` before simulating the hotkey: if the saved target is the Claude session itself, the test dictation is typed into that session. Windows TTS (`System.Speech`) plus `keybd_event` for the hotkey makes it possible to test the whole pipeline without speaking.

## Known limitations / next steps

- Recording is toggled with the hotkey (press to start, press again to stop) because Electron's `globalShortcut` reports no key-up. True push-to-talk is now possible with the uiohook key-up events that are already loaded.
- Some games, especially ones with anti-cheat or exclusive full-screen, may swallow `RegisterHotKey`. This hasn't been tested with real games yet.
- With `language: "auto"`, short utterances can be detected as the wrong language. Pin `en` or `ro` if this happens.
- Elevated (admin) terminals can't be attached to from a non-elevated app.
